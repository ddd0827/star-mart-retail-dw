# 业务背景与流程说明

## 1. 业务背景

本项目虚构了一家名为「星选生活 STAR-MART」的连锁零售企业，业务覆盖线下门店与线上渠道：

- 6 个大区、12 个城市、24 家线下门店（旗舰店、标准店、社区店、奥莱店各具定位）
- 1 个线上履约仓，服务微信小程序、APP、第三方平台
- 52 个两级品类、80 个品牌、1,500 个 SKU、25 家供应商
- 10 万会员，按普通/银卡/金卡/黑卡分层
- 数据窗口：2026-04-20 至 2026-10-16（180 天）

所有姓名、手机号、门店、品牌均为模拟数据；手机号已脱敏，不包含真实个人信息。

## 2. 端到端业务流程

```
供应商 ──采购/补货──> 线上履约仓 / 门店库存
                         │
会员/顾客 ──到店/线上访问──> 浏览与加购 ──> 下单 ──> 支付 ──> 履约/自提
                         │                                      │
                         └────────── 库存扣减 <──────────────────┘
                         │
                         └── 退款/退货申请 ──> 退款完成 ──> 退货入库（可选）
```

### 2.1 商品与供应链

1. 采购/商品团队维护品类、品牌、SKU、供应商、进价与售价。
2. 各门店按店型获得不同铺货范围（社区店以食品/生鲜为主，旗舰店全品类，奥莱侧重服饰/家居）。
3. 线上履约仓覆盖约 95% 的 SKU，负责线上订单发货。
4. 库存管理按「期初 + 采购入库 − 销售出库 + 退货入库 ± 盘点调整 = 期末」记账。
5. 当库存低于安全库存时触发补货；供应商提前期为 2–5 天；少量紧急补货保证账实一致。

### 2.2 会员运营

1. 顾客通过门店、小程序、APP、公众号或电商平台注册会员。
2. 会员等级与购买倾向相关；等级越高，复购概率和专属折扣越高。
3. 每月 8/18/28 日为会员日，会员订单享受额外优惠。
4. 会员可绑定线下/线上订单，用于会员销售占比、RFM、留存与复购分析。

### 2.3 线下门店交易

1. 各门店每天产生客流（受店型、城市、星期、节假日、促销影响）。
2. 客流按转化率转化为线下订单；会员订单约占 65%，其余为散客。
3. 顾客在门店营业时间（10:00–22:00）完成选购与支付。
4. 支付方式包括微信、支付宝、银联、现金、储值卡。

### 2.4 线上交易与行为

1. 用户通过小程序/APP/第三方平台进入线上店铺，产生会话。
2. 会话按漏斗推进：访问 → 浏览商品 → 搜索 → 加入购物车 → 进入结算 → 支付。
3. 支付成功的会话与线上订单一一对应；行为日志记录曝光、点击、搜索、加购、结算、支付事件。
4. 大促（618、国庆等）提升线上会话数量与支付转化率。

### 2.5 支付、退款与履约

1. 支付成功后生成支付流水；取消订单保留失败支付流水，不计入销售。
2. 约 3%–10% 的订单发生退款（线上高于线下、服饰/数码高于食品），退款原因包括七天无理由、质量问题、不喜欢、发错货等。
3. 退款可全额或部分行退款；退货退款在 1–3 天后回补库存。
4. 退款金额不超过对应订单行实付金额；退款状态包含已完成与处理中。

### 2.6 经营分析

- 总部每日关注：GMV、净销售额、订单量、客单价、退款率、会员/线上占比、毛利率。
- 门店管理：门店排名、客流转化、月度目标达成。
- 商品与品类：品类结构、Top 商品、毛利与退款。
- 会员：RFM 分层、留存 cohort、月度复购。
- 供应链：库存周转、缺货率、售罄率。
- 营销：线上漏斗、促销增量与投入产出观察指标。

## 4. 模拟数据规则（真实感设计）

### 4.1 时间与节假日

- 数据窗口 2026-04-20 至 2026-10-16。
- 节假日：劳动节（5/1–5/5）、端午节（6/19–6/21）、中秋节（9/25–9/27）、国庆节（10/1–10/7）。
- 大促：五一、618（6/1–6/18）、国庆。
- 会员日：窗口内每月 8、18、28 日。
- 周末客流与线上会话高于工作日；节假日和促销进一步放大。

### 4.2 驱动式生成（不是各表独立随机）

1. **主数据**：门店、SKU、会员、活动等先固定随机种子生成。
2. **门店客流**：基础客流 × 店型/城市/星期/节假日/促销因子 → 泊松分布客流。
3. **线下订单**：客流 × 转化率 → 二项分布订单数。
4. **线上会话**：按日生成会话数，并生成浏览、搜索、加购、结算、支付漏斗标识。
5. **线上订单**：支付会话与线上订单一一对应，行为日志的支付事件携带订单号。
6. **订单明细**：按门店铺货范围、品类季节性、商品长尾热度抽样 SKU，生成数量、价格、折扣与成本。
7. **支付与退款**：支付成功/失败、退款行、退货数量、退款原因与延迟。
8. **库存**：用真实订单出库与退货入库驱动日库存流水，低于安全库存触发补货。
9. **脏数据**：只在 raw 层注入重复、空值、非法数量、混合时间格式等，DWD 负责清洗。

### 4.3 商品与门店差异

- SKU 热度为长尾分布，少量爆款贡献主要销量。
- 社区店偏食品/生鲜；旗舰店全品类；奥莱偏服饰/家居；线上仓覆盖广。
- 品类有月度季节因子（夏季生鲜饮料、秋季服饰、节庆食品礼盒等）。
- 价格、成本、保质期按品类范围生成，部分商品为短保生鲜。

### 4.4 退款与右删失

退款按订单渠道和品类概率生成，退款延迟 0–14 天。数据窗口末期的订单可能尚未发生退款，因此整体退款率会略低于理论值；这是真实业务中常见的右删失现象，文档与指标口径中已说明。

### 4.5 库存与采购

- 每个库位只对铺货 SKU 维护库存。
- 初始库存按窗口日均销量外推 25–40 天；安全库存为若干天销量。
- 低于安全库存且未在途时触发补货，提前期 2–5 天。
- 销售出库来自有效支付订单行；退货入库来自已完成退货退款。
- 期末库存不足时触发紧急补货，保证每天库存守恒且非负；紧急补货比例应低于 0.5%。
- 日快照字段满足：`期初 + 采购入库 − 销售 + 退货 + 调整 = 期末`。

## 5. 数据一致性约束

生成器在写入 raw 前保证以下关系（DWD/质量规则再次验证）：

- 有效订单行金额 + 运费 = 订单实付 = 成功支付金额。
- 支付会话数 = 线上有效支付订单数。
- 线下订单数 ≤ 门店客流。
- 退款金额 ≤ 对应订单行金额。
- 库存每日守恒且非负。
- 会员注册日期 ≤ 下单日期。
- 同一批次重跑结果可复现（固定随机种子与稳定订单号）。
